# Tech-Quest 要件定義書

## 1. 文書概要

- システム名: Tech-Quest
- 目的: ITコンサル新人研修における課題提出、レビュー、ナレッジ共有を一元管理する
- 想定利用者:
  - 受講生
  - メンター
  - 管理者

## 2. 背景

従来はスプレッドシート中心で課題進捗や提出物を管理していたが、提出件数の増加により、レビューの滞留、課題定義の更新負荷、ナレッジ共有の難しさが顕在化していた。そこで、課題一覧、提出、AI一次レビュー、メンター評価、ナレッジ共有までを一体化した Web システムへ移行する。

## 3. システムの目的

- 受講生が課題を選び、README とモック画像を主提出物として提出できるようにする
- AI による一次レビューで、README の内容や合格条件との整合を事前に確認する
- メンターが採点と差し戻しを効率的に行えるようにする
- 合格済みの良い提出を匿名のナレッジとして次の受講生へ共有する

## 4. 対象業務

### 4-1. 受講生業務

- 課題一覧の閲覧
- 課題詳細の確認
- README とモック画像の提出
- 自分の提出状況確認
- AI レビュー / メンター評価の確認
- ナレッジ閲覧

### 4-2. メンター業務

- 提出レビュー一覧の確認
- 受講生単位の担当設定
- AI レビュー結果の確認
- 技術点 / ビジネス点 / コメント / 判定の登録
- 合格提出のナレッジ公開

### 4-3. 管理者業務

- 課題マスタ編集
- ユーザーロール管理
- 受講生担当設定
- ナレッジ公開の管理

## 5. 機能要件

### 5-1. 認証

- Google Workspace ログインに対応する
- 初回ログイン時ロールは `student` とする
- 管理者がロール変更できる

### 5-2. 課題管理

- 課題一覧を表示できる
- 課題詳細に目的、提出物、合格条件、AI レビュー観点を表示できる
- 管理者が課題文言を編集できる

### 5-3. 提出

- 対象課題を選択して提出できる
- README は必須
- モック画像は必須
- 補足リンクは任意
- 提出内容は Supabase に保存する
- モック画像は Storage に保存する

### 5-4. AI 一次レビュー

- README を主対象としてレビューを行う
- 合格条件との整合をチェックする
- スコア、要約、指摘、メンター確認ポイントを保存する

### 5-5. メンター評価

- メンターまたは管理者のみ登録できる
- 技術点 / ビジネス点 / コメント / 判定を保存できる
- 提出ステータスに反映する

### 5-6. 担当設定

- 担当は提出単位ではなく受講生単位とする
- mentor は自分を担当に設定 / 解除できる
- admin は任意メンターを割り当て / 解除できる

### 5-7. ナレッジ共有

- 合格済み提出のみ公開対象とする
- 公開時は提出者名を出さない
- README、メンターコメント、モック画像を課題単位で見られる
- 課題ごとに複数の公開ナレッジを保持できる

### 5-8. 通知

- 提出完了時に Slack 通知
- AI レビュー完了時に Slack 通知
- メンター評価保存時に Slack 通知

## 6. 非機能要件

- 社内利用を前提とした認証・認可
- RLS による DB レベル制御
- 画像や README を扱いやすい提出 UX
- 縦に長すぎず、レビューしやすいレイアウト
- 今後の課題追加や rubric 変更に耐える構造

## 7. 画面一覧

- ログイン
- ホーム
- 課題一覧
- 課題詳細
- 課題提出
- 提出状況
- 提出詳細
- 担当設定
- 提出レビュー一覧
- レビュー詳細
- 課題管理
- ユーザー管理
- ナレッジ一覧
- ナレッジ課題詳細

## 8. 提出物方針

提出物の主構成は以下とする。

- README
- モック画像
- 任意の補足リンク

GitHub リンクは必須としない。

## 9. ナレッジ公開方針

- 公開対象は `passed` の提出のみ
- 提出者名は表示しない
- 学べる要素に絞って表示する
  - README 要約
  - README 本文
  - メンターコメント
  - モック画像

## 10. 今後の拡張候補

- Google Docs API を用いた文書自動生成
- ナレッジ公開の承認フロー
- README テンプレートの課題別自動差し込み強化
- ナレッジへのコメントやお気に入り
