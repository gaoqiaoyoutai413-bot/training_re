# システム機能概要

## 1. システムの目的

Tech-Quest は、IT コンサル新人研修における `課題提示`、`提出`、`AI 一次レビュー`、`メンター評価`、`ナレッジ共有` を一つの Web システムにまとめた研修運用プラットフォームです。

従来のスプレッドシート中心の運用では、提出管理、レビュー滞留、評価基準の共有、良い提出の再利用が分散しやすいため、現在のシステムでは以下を一体化しています。

- 課題一覧と課題詳細の管理
- README とモック画像を中心とした提出
- Gemini による AI 一次レビュー
- メンターによる技術点・ビジネス点の採点
- 合格提出の匿名ナレッジ公開
- Slack 通知
- Google Docs への要件定義書・設計書出力

## 2. 現在の主要機能

### 2-1. 認証・ユーザー管理

- Google ログイン
- 初回ログイン時の `student` ロール自動付与
- `student / mentor / admin` のロール管理
- 管理者によるロール変更

### 2-2. 課題管理

- 課題一覧の表示
- 課題詳細の表示
- 合格条件、AI レビュー rubric、メンター評価シートの表示
- 管理者による課題内容の編集

### 2-3. 提出管理

- README を主提出物とする提出フォーム
- モック画像の必須提出
- 補足リンクの任意提出
- 提出状況一覧
- 提出詳細表示

### 2-4. AI 一次レビュー

- 提出後に Gemini による一次レビューを実行
- セキュリティ / 可読性 / ビジネス価値の 3 観点スコア
- 要約、指摘一覧、改善提案の表示
- 合格条件チェックの表示

### 2-5. メンター評価

- メンターによる採点入力
- 技術点 / ビジネス点 / 判定 / コメントの保存
- レビュー済み内容の表示
- 差し戻し / 合格の更新

### 2-6. 担当設定

- 受講生単位で担当メンターを設定
- mentor は自分を担当に設定 / 解除
- admin は任意メンターを割り当て / 解除

### 2-7. ナレッジ共有

- 合格済み提出からナレッジ公開
- 提出者名を出さない匿名公開
- 課題ごとのナレッジ一覧
- README、メンターコメント、モック画像の閲覧

### 2-8. 通知・文書出力

- 提出時の Slack 通知
- AI レビュー完了時の Slack 通知
- メンター評価保存時の Slack 通知
- Google Docs への要件定義書 / 設計書出力

## 3. 利用者ごとの主な利用シーン

### 受講生

- 課題を選ぶ
- README とモック画像を提出する
- AI レビューとメンター評価を確認する
- ナレッジを見て次の提出改善に活かす

### メンター

- 提出レビュー一覧を確認する
- 受講生ごとの担当設定を行う
- AI レビューを見ながら採点する
- 良い提出をナレッジとして公開する

### 管理者

- 課題定義を編集する
- ユーザーのロールを管理する
- 担当設定を管理する
- Google Docs へ要件定義書・設計書を出力する

## 5. 現在の提出方針

現状のシステムでは、提出時に GitHub リンクを必須としていません。主提出物は以下です。

- README / 提出内容
- モック画像

必要に応じて補足リンクを添える構成です。AI 一次レビューも README を最優先で読みます。
