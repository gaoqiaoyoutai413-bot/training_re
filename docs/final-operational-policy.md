# 最終運用ポリシー

## 1. 目的

この文書は、Tech-Quest を本番運用へ進めるために確定した運用ルールをまとめた最終ポリシーです。  
提出、レビュー、ナレッジ公開、通知、権限、文書出力、データ保持に関する判断基準をここで固定します。

## 2. 確定事項一覧

### Step 1. 提出ルール

- README: 必須
- モック画像: 必須
- 補足リンク: 任意

### Step 2. AIレビューの位置づけ

- AIレビューは参考情報として扱う
- 最終判定は mentor が行う

### Step 3. ナレッジ公開ルール

- 公開対象は `passed` の提出のみ
- `mentor` または `admin` が公開する
- 公開内容は `README / メンターコメント / モック画像`
- 提出者名は公開しない

### Step 4. メンター担当ルール

- 担当は課題単位ではなく `人単位`
- `mentor` は自分を担当に設定 / 解除できる
- `admin` は任意の mentor を設定 / 解除できる

### Step 5. Slack通知ルール

- レビュー用チャンネル通知
  - 提出
  - AIレビュー完了
  - 合格
  - 差し戻し
- student への DM 通知
  - メンター評価完了
  - 合格
  - 差し戻し

## 3. 権限と運用ルール

### Step 6. 管理者運用ルール

- `admin` は運営責任者のみ
- `admin` が行うこと
  - 課題編集
  - ロール変更
  - 担当設定上書き
  - Google Docs 出力
  - ナレッジ管理
- `mentor` 昇格は `admin` が行う
- 初回ログイン時のロールは `student`

## 4. 文書出力ルール

### Step 7. Google Docs 出力の位置づけ

- Google Docs 出力は社内共有用の整形版とする
- 正式な原本は `システム内データ` と `リポジトリ内 docs` に置く
- `admin` のみが出力できる
- 出力対象
  - 要件定義書
  - 設計書
  - 社内説明用サマリー

## 5. データ保持ルール

### Step 8. 本番データ保護 / 保管ルール

- README、モック画像、AIレビュー、メンター評価は研修履歴として保持する
- ナレッジ公開物は匿名化して継続利用する
- 退職後はログイン不可にするが、提出履歴は内部保持する
- 削除は `admin` 判断で個別対応する

## 6. 本番運用時の前提

本番運用では以下を前提とします。

- 提出物は GitHub ではなく README とモック画像を中心に扱う
- AI は補助であり、評価責任は mentor が持つ
- 良い提出は匿名ナレッジとして再利用する
- admin は運用統制の役割に限定する
- Google Docs は配布用資料であり、原本管理先ではない

## 7. 今後の実装・運用反映ポイント

このポリシーに基づいて、今後は以下をシステムへより明示的に反映していく。

- 提出フォームの必須表示
- AIレビューの文言整理
- ナレッジ公開条件の UI 明示
- Slack 通知のイベント整理
- DM 通知連携
- admin / mentor の役割説明の画面反映
- データ保持方針の運用手順化
