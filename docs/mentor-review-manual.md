# メンター向けレビュー運用マニュアル

## 1. このマニュアルの目的

このマニュアルは、Tech-Quest でメンターがレビューを行うときの基本手順と判断基準を揃えるための研修用資料です。  
レビュー品質を安定させ、受講生にとって分かりやすいフィードバックを返せる状態を目指します。

## 2. まず理解しておくこと

- AIレビューは `参考情報`
- 最終判定は `mentor`
- 受講生が次に改善できるよう、具体的で再現可能なコメントを返す
- 自分の提出物はレビューしない

## 3. メンターが使う主な画面

### 提出レビュー

- `/mentor/reviews`
- 提出一覧を確認する
- 受講生名で検索する
- 自分の担当だけを見る

### レビュー詳細

- `/mentor/reviews/[id]`
- README
- AIレビュー
- モック画像
- コード提出
- 既存の評価結果
を 1 画面で確認する

### 担当設定

- `/mentor/assignments`
- 自分の担当受講生を設定 / 解除する

## 4. レビューの基本手順

### Step 1. README を読む

最初に確認するのは README です。特に以下を見ます。

- 何を作ったのか
- 課題の業務課題にどう効くのか
- 必須機能をどう満たしたか
- エラーハンドリングをどう考えたか
- 今後の改善点があるか

README が弱い場合は、実装が良くても評価を上げすぎないようにします。

### Step 2. モック画像を見る

- README の説明とモック画像が一致しているか
- ユーザーがどのように使うかが見えるか
- 実務で使うイメージが湧くか

### Step 3. コード証跡を見る

- コード提出リンク
- コードファイル
- 補足リンク

があれば確認します。  
コード証跡がない場合は、README とモック画像ベースの暫定評価になります。

### Step 4. AIレビューを確認する

AIレビューでは次を優先して見ます。

- 合格条件チェック
- high severity 指摘
- `AI評価の見立て`
- メンター確認ポイント

AI の点数だけで判断せず、根拠の書き方まで確認します。

### Step 5. メンター評価を入れる

評価項目:

- 技術点
- ビジネス点
- 判定
  - `passed`
  - `rework_requested`
- コメント

## 5. 判定の基本方針

### `passed` にしやすい状態

- 必須要件が大筋で満たされている
- README から実装意図が分かる
- モック画像で利用イメージが分かる
- 大きなセキュリティ懸念がない
- 業務価値が具体的に説明されている

### `rework_requested` にすべき状態

- 必須要件が未達
- README が薄く、何を作ったか分かりづらい
- 業務価値の説明が抽象的
- モック画像が不足している
- 高 severity の懸念がある

## 6. コメントの書き方

### 良いコメントの型

1. 良かった点
2. 修正してほしい点
3. 次に何を直せば通過に近づくか

例:

```text
README から業務課題と実装方針が分かりやすく、モック画像も操作イメージが伝わりました。
一方で、必須機能のうちエラーハンドリングの説明が弱く、未入力時の挙動が確認しづらいです。
未入力時の処理と、その根拠を README に追記したうえで再提出してください。
```

### 避けたいコメント

- 抽象的すぎる
- 何を直せばいいか分からない
- 人を評価していて、提出物を評価していない

## 7. AIレビューをどう使うか

### 使い方

- AI を最初のチェックリストとして使う
- 自分が見落としていないかの補助にする
- 受講生への改善ヒントの整理に使う

### 使い方として避けること

- AI の点数だけで合否を決める
- AI が `strong` だから無条件で合格にする
- AI が低評価だから現物を見ずに差し戻す

## 8. 担当運用

- 担当は `人単位`
- mentor は自分を担当に設定 / 解除できる
- admin は任意の mentor を設定 / 解除できる

担当受講生の提出は優先してレビューします。

## 9. Slack 通知との関係

レビュー時に発生する通知:

- メンター評価完了
  - 対象 student へ DM
- 合格
  - レビュー用チャンネル
  - 対象 student へ DM
- 差し戻し
  - レビュー用チャンネル
  - 対象 student へ DM

## 10. 困ったときの確認順

判断に迷ったら、次の順で確認します。

1. README に課題要件との対応が書かれているか
2. モック画像で利用シーンが見えるか
3. AIレビューの `acceptanceChecks`
4. AIレビューの high severity 指摘
5. 必要なら admin または他 mentor に相談する

## 11. メンター研修で伝えるべきポイント

- AI は補助、最終責任は mentor
- README とモック画像をまず見る
- 点数より根拠を見る
- コメントは改善可能な形で返す
- 自分の提出物はレビューしない
